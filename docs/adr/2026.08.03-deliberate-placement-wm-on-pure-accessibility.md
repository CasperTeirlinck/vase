# Deliberate-placement window manager on pure Accessibility

## Context

Vase brings a tmux philosophy to native OS windows. A window manager, unlike tmux, renders nothing an app draws:
it can only move, resize, raise, hide, and focus native windows, and draw its own overlays. Two independent choices:

1. **How windows are placed.** Automatic space-filling (binary space partitioning, like the yabai/i3 default)
   reflows every window the moment it opens; the algorithm owns placement.
   Deliberate placement (tmux-like) keeps a workspace showing one window until the user explicitly splits or stacks.
2. **How windows are controlled on macOS.** The Accessibility API works without disabling SIP
   but cannot truly reorder/stack windows in the WindowServer.
   yabai achieves richer control (instant stacks, space management)
   only by disabling SIP and injecting via private APIs.
   That is powerful but fragile across OS updates, and a security and setup burden.

## Options

1. **Full BSP auto-tiler + SIP-off private APIs.** Maximal control, instant stacks, automatic layout.
   Fights macOS hardest; fragile across updates; security posture and setup friction; least portable.
2. **Deliberate placement + real stacks, on pure Accessibility.** New windows become tabs in the current workspace;
   the user splits/stacks/moves on purpose;
   stacks are real (window groups with overlay tab bars). No SIP, no private APIs.
3. **AeroSpace-style: pure Accessibility but no real stacks** (accordion only).
   Safe, but drops the crown-jewel tabbed-stack feature.

## Recommendation

Option 2. The user's tmux superpowers are navigation and grouping, not automatic space-filling: tmux never auto-tiles;
the user places panes on purpose. Deliberate placement matches that instinct and leans on fewer fragile OS behaviors,
making it _more_ portable to Windows/Linux later. Pure Accessibility avoids the SIP burden;
real stacks (the emotionally load-bearing feature) are kept, accepting the latency risk addressed in a separate ADR.

## Decision

Adopt **deliberate placement with real stacks, on pure Accessibility, no SIP**.
Rejects both BSP auto-tiling (option 1's automation) and yabai's SIP-off private-API control.
The core model stays platform-agnostic behind a thin backend trait; macOS is the first backend,
Windows/Linux deferred (Wayland is the known hard case).

**Refinement (2026-08-08):** matching an `AXUIElement` to a specific window requires reliable identity:
geometry fails for same-app windows co-located in a stack (they share a frame).
The backend uses `_AXUIElementGetWindow`,
a private but **read-only, SIP-compatible** HIServices function that returns an element's CoreGraphics window id
(the same primitive AeroSpace uses). This does not violate the "no SIP / no injection" stance:
it disables nothing and injects nowhere.
It is a lookup, not the WindowServer-injection class of private API this ADR rejects.
