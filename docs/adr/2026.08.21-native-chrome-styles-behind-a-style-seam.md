# Native chrome styles behind a style seam

## Context

vase's chrome was one look everywhere: the interlocking powerline bar, laid out in `vase-core` and
drawn by each platform. `chrome::bar` handed the painter a `BarLayout` of notches, bulges, a lead
pill and a nesting radius, and the "theme" was a nine-color palette.

To draw for example a Liquid Glass chrome on macOS, none of that is expressible as a palette over powerline geometry,
and none of it belongs in a platform-agnostic crate. Windows will want the same freedom for Mica and Fluent.

So the powerline shapes have to stop being the core bar model and become one of the styles, and the theme has
to grow from a palette into a style plus a palette.

## Options

1. **Branch inside `chrome::bar`.** Add the native metrics next to the powerline ones and let the
   painter switch. Smallest diff, but every platform's design language accretes in the shared crate,
   and the core would carry AppKit-shaped constants it cannot render.
2. **Move all bar layout into the platform crates.** Honest seam, but the powerline bar is genuinely
   cross-platform: its proportions would be duplicated in AppKit and Direct2D and drift apart.
3. **Keep the semantic bar in the core, make layout a style's job.** `chrome::bar` says _what_ a bar
   shows (`Bar`, `BarTab`, the run order, ellipsizing, text measurement); `chrome::powerline` is one
   style any platform can lay out with; a platform that has a native style lays it out itself. The
   painter returns each tab's clickable span so click routing does not care who laid it out.

## Recommendation

Option 3. The split follows what is actually shared: the content of a bar and the order of its runs
are the same everywhere, the shapes and materials are not.

The palette stays in the core for the powerline style. The native style ignores it and reads the
system's own colors instead, which is the whole point of being native: appearance and accent color
follow the user, not the config.

## Decision

- `chrome::bar` holds the semantic bar and the shared content metrics; `chrome::powerline` holds
  vase's own style; `Painter::bar` takes a `Bar` and returns the tab spans clicks route against.
- `chrome::theme::Theme` is now a `Style` (`native` or `powerline`) plus a `Palette`.
- macOS implements `native` as Liquid Glass (`NSGlassEffectView`, vibrancy before macOS 26) with
  system colors and the system font, and it is the default there.
- Windows has no native style yet, so `native` draws the powerline one; when its Mica/Fluent chrome
  lands it slots in behind the same seam, and no config changes.
